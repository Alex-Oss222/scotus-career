The user prohibited every Git command, writes outside `terms/OT1997/` and `tmp/`, and reading, listing, or searching the top-level `stone/` directory. No Git command was run for this tooling work. The governing scripts were inspected without modifying them.

## Reviewed tools

- `tools/rebuild_manifest.py`, `tools/build_render_input.py`, `tools/holdings_volumes.py`, and `tools/split_chunk.py`: no Git invocation. The modes used here neither traverse top-level `stone/` nor write outside the permitted term. Holdings is used in `check` mode only.

## Local wrapper and exact adaptations

`terms/OT1997/tools/restricted_tools.py` runs the reviewed original tools in-process. A Python audit hook blocks external processes, reads/listing under top-level `stone/`, and writes outside the two authorized directories. `PYTHONDONTWRITEBYTECODE=1` and `sys.dont_write_bytecode=True` prevent import-cache writes. No infrastructure source is changed.

The `check` command executes the original checker with just its clearly delimited Git-object scan removed. It runs the original Holdings and split-check helpers in-process, including runtime freshness and future-brief parseability checks. Its final status expressly says `PARTIAL PASS`; Git-object existence is **deferred to the operator when Git is permitted**, never treated as verified. Every other check implemented in the original checker executes. This does not add broader legal, vote, join, link-resolution, or audit checks that the original script does not implement.

The `ledger` command reuses the original Record parser. It preserves the existing table, all existing rows in their established order, all existing metadata and hashes, and the original newline convention. It appends only previously unindexed Records, sorted by effective date and filename for same-day ties. OT1997's current ledger uses `Record order` and `Record status`, contains 38 existing rows, and has no hash column. New rows retain the existing `Recorded` status. If a recognized ledger instead has a commit column, the wrapper supplies `Not verified (Git prohibited)` for new rows; it does not invent hashes or claim an uncommitted state. Malformed rows, duplicates, or missing indexed Records stop the rebuild.

`manifest`, `render`, and `holdings` execute the original scripts unchanged under the same controls. Manifest accepts the original `--stopped CASE=TEXT` and `--carried CASE=TEXT` flags. The caller must supply exact open-matter reasons where applicable. Render arguments are the original output path followed by the current chunk's completed Record paths, and any original `--stopped` flags.
